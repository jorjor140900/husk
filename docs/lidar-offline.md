# ดู LiDAR จาก bag บนคอม โดยไม่ต้องมีหุ่น

ใช้ไฟล์ `.bag` ที่บันทึกไว้แล้ว ไม่ต้องต่อ Wi-Fi ของหุ่น ไม่ต้อง SSH
ไม่ต้องเปิด ROS, RViz, กล้อง หรือ bridge และไม่ต้อง build workspace

## เปิดผลที่สร้างไว้

ไฟล์ `replay.html` เปิดด้วย Firefox หรือ Chrome ได้โดยตรง ไม่ต้องติดตั้งอะไร
กด **Play**, เลื่อนเวลา หรือกด **±1 เฟรม** เพื่อดูทีละ scan
ใช้เมนูระยะมองเพื่อสลับระยะใกล้/ไกล

- สีส้ม: scan ที่บันทึกมาจริง
- สีเขียว: ผลทดลองเลือกจุดใกล้ที่สุดจาก ring และช่องมุมเดียวกับ scan เดิม
- กราฟด้านข้าง: จุด 3 มิติเทียบความสูงจาก `base_link` เฉพาะแถบ |Y| < 0.6 m

ค่านี้เป็นการเปรียบเทียบข้อมูลในคอม ไม่ได้เปลี่ยน scan, costmap หรือคอนโทรลบนหุ่น
ไม่มีการลบสิ่งกีดขวางตามความสูง ไม่มีการเติมช่องที่ไม่มี return ว่าเป็นทางว่าง

## สร้างผลเองบนคอม Ubuntu

เตรียม environment สำหรับวิเคราะห์แยกจาก AI environment เดิม ครั้งเดียว:

```bash
cd ~/husk-live
git pull --ff-only origin work
python3 -m venv .venv-lidar-review
.venv-lidar-review/bin/python -m pip install -r requirements-lidar-review.txt
```

รันกับไฟล์ที่ส่งมา โดยแก้ `--bag` ให้ตรงกับที่เก็บไฟล์จริงบนคอม:

```bash
cd ~/husk-live
.venv-lidar-review/bin/python tools/replay_lidar_bag.py \
  --bag "$HOME/Downloads/husky-ghost-20261030-050159.bag" \
  --output outputs/ghost-replay
xdg-open outputs/ghost-replay/replay.html
```

เลือก output directory ใหม่เมื่อต้องการรันซ้ำ เครื่องมือไม่เขียนทับผลเดิม
เครื่องมืออ่านข้อมูลอย่างเดียว ไม่ import `rclpy`/`rospy` และไม่ publish topic
รายงานตัวเลขอยู่ที่ `outputs/ghost-replay/report.json`

## ผลที่ทดสอบได้จากไฟล์นี้

`husky-ghost-20261030-050159.bag` สร้าง scan เดิมซ้ำได้ครบ 34 เฟรมจาก ring 8
ผลทดลองยังเก็บ finite returns ทั้ง 29,604 ช่อง-เฟรม และช่องไม่มี return ทั้ง 894
พบ 610 ช่อง-เฟรมที่ scan เดิมไกลกว่าจุดใกล้ที่สุดเกิน 1 m สูงสุดประมาณ 32.747 m
เป็นการรวมหลายมุมย่อยในช่องเดียว ไม่ใช่ข้อสรุปว่า LiDAR วัดผิด
การเลือกจุดใกล้ช่วยรักษา return ที่ใกล้กว่า แต่ไม่ได้พิสูจน์ว่าเป็นวิธีแก้กรอบสีฟ้าที่หน้างาน

Bag นี้หุ่นอยู่นิ่งและผู้ใช้บันทึกหลังย้ายออกจากสถานที่เกิดปัญหา
ไม่มีภาพกล้อง, global costmap หรือ map-to-odom ที่ใช้งานบนคอมให้เทียบพร้อมกัน
ดังนั้นยังทดสอบเส้นเหลืองจากภาพ, การสะสมจุดใน Nav2 หรืออาการขณะหุ่นจริงเคลื่อนที่ไม่ได้
หน้าดูย้อนหลังใช้พิกัด base_link ของแต่ละเฟรม ไม่ใช่การจำลอง Nav2 หรือผลยืนยันความปลอดภัย

การแก้ระบบจริงยังต้องรักษาสิ่งกีดขวางเรียลไทม์ ไม่ใช้ผลออฟไลน์นี้ปิด obstacle layer
หรือข้าม watchdog/permission ของหุ่น

# บันทึกแก้ regression ของ RGB baseline

## ปัญหาและสาเหตุ

รุ่น `f49a664` ใช้สี Lab ใกล้จุดเริ่มเป็นตัวแทนพื้นทั่วภาพ ไม่มีขอบภาพกั้นการขยายพื้นที่ จึงรวมเสา/ผนังที่สีคล้ายพื้นเป็น drivable mask ได้ แม้สีเขียวจะเชื่อมกับพื้นอยู่ก็ตาม
ตัว planner ให้น้ำหนักคะแนนสีมากกว่าระยะจากขอบ ทำให้ reference เบนตามสี รอยแตก และแสงสะท้อน ค่า `quality_score` สูงเพียงบอกว่าคะแนนสีตามเส้นทางสูง ไม่ได้ยืนยันว่าพื้นจริงผ่านได้

## พฤติกรรมหลังแก้

- ขยายพื้นที่จาก seed ตามสีเพื่อนบ้าน โดยใช้ขอบ Canny กั้นเป็นค่าเริ่มต้น เก็บขอบเหล่านี้เป็นหลักฐานลบ ไม่เติมรูหรือใช้ history เปิดพื้นที่กลับมา
- ให้น้ำหนักระยะห่างจากขอบมากกว่าสี เพิ่มค่าปรับการเปลี่ยนทิศทาง และค้นหาเส้นโค้งเรียบจากชุดจำกัด ตรวจทุกพิกเซลระหว่างจุดกับ mask ที่เว้นระยะขอบแล้ว
- คืน `no_smooth_reference` เมื่อไม่มีเส้นโค้งในชุดที่ค้นหาผ่านการตรวจ แม้มีเส้นทางแบบจุดที่หักมุมได้ ไม่มีการวาดเรฟเก่าค้าง
- เอา `quality_score` ออกจากหน้าจอ เก็บไว้ใน metadata สำหรับวินิจฉัย พร้อม `quality_score_is_safety_confidence: false` เส้นกลางหุ่นและเส้นขอบแดงยังเป็นภาพประกอบในพิกัดภาพ

นี่เป็นการลดข้อผิดพลาดบางประเภท ไม่ใช่การแก้ semantic segmentation สำเร็จ ขอบเงาคม รอยแตก และแสงสะท้อนอาจตัดพื้นจริง ขอบเสาที่ไม่ต่อเนื่องยังปล่อยให้สีลามขึ้นเสาได้ เส้นโค้งเรียบก็ยังอ้อม texture ที่ถูกตรวจผิดเป็นสิ่งกีดขวางได้

## หลักฐานตรวจสอบ

ใช้ PNG ต้นฉบับ 6 เฟรมที่คัดไว้จาก part2–part4: part2 เฟรม 125/263, part3 เฟรม 278/571, part4 เฟรม 0/139 ไม่ทดสอบ part1 ซ้ำ และไม่ได้รันภาพ screenshot ที่มี overlay เป็นข้อมูลต้นฉบับ
ใช้จุดตรวจร่างจากการดูภาพชุดเดิม 36 จุด แบ่งเป็นพื้นอนุญาต 18 จุด และสิ่งกีดขวาง 18 จุด ไม่มี dense ground truth หรือชุดทดสอบอิสระ ตัวเลขนี้จึงไม่ใช่ accuracy outdoor

สองจุดที่ยังรับผิดเป็นทางอยู่บนเสาใน part2 เฟรม 125 ที่พิกัด (55,200) และ (267,152) อ้างอิงภาพขนาด 640×360
จุดพื้นจริงที่ถูกปฏิเสธ 4 จุดอยู่ใน part3 เฟรม 278 จำนวน 3 จุด และ part4 เฟรม 0 จำนวน 1 จุด
จำนวน path ที่ลดลงไม่ใช่คะแนนความแม่นยำ: หลังแก้มีจุดเริ่มใช้ไม่ได้ 1 เฟรม และไม่มี smooth reference 2 เฟรม

ตรวจการทำงานต่อเนื่องเพิ่มเติม 60 เฟรมแรกของ part4 โดยไม่ข้ามเฟรมหรือรีเซ็ต history: ก่อนแก้มี path 60 เฟรม หลังแก้มี `limited_lookahead` 37 เฟรม, `no_smooth_reference` 16 เฟรม และ `start_blocked_or_too_narrow` 7 เฟรม ไม่ได้วัดความนิ่งที่หักการเคลื่อนกล้องหรือความถูกต้องของ mask ทุกเฟรม
เวลา detector เฉลี่ยใน cloud ครั้งนี้ประมาณ 82.2 ms ก่อนแก้ และ 93.8 ms หลังแก้ ไม่รวม I/O และไม่ใช่ benchmark ของเครื่องบนหุ่น

ผลเทียบภาพ, JSON รายจุด, snapshot source ก่อน/หลัง และวิดีโอเทียบสั้นเก็บใน `outputs/regression-investigation/final-comparison/` ของ cloud ซึ่งถูก Git ignore ไว้ จึงไม่ติดไปกับ `git pull`

รัน `python -m unittest discover -s tests -v` ผ่าน 36 tests รวมการหลบสิ่งกีดขวาง การไม่ตัดมุม/ข้ามรู การปฏิเสธทางหักมุม การไม่ไล่สี และการล้าง temporal history
การทดสอบเงาคมเต็มทางของเดิมยังคง assertions เดิม แต่ระบุให้ตรวจเมื่อปิด edge barrier; ค่าเริ่มต้นใหม่อาจกั้นขอบชนิดนี้ จึงเพิ่มการตรวจเงาเปลี่ยนทีละน้อยและการไม่เติมข้ามขอบแยกกัน

ยังไม่ได้ทดสอบ webcam จริงใน cloud ไม่มีโมเดล AI ใหม่หรือการเชื่อมหุ่นในงานแก้นี้ ขั้นต่อไปสำหรับความหมายของพื้น/เสา/พรมคือทำ label ภาพต้นฉบับและประเมิน segmentation บนคลิปที่แยกจากชุดฝึก ตามนโยบายพื้นขาวใต้ตึกอนุญาต แต่พรมทุกสีห้ามผ่าน

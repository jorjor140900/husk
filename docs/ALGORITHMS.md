# อัลกอริทึมของระบบล่าสุด

## 1. การตรวจจับพื้นที่

SegFormer ให้ probability ของ drivable ในแต่ละพิกเซล จากนั้นใช้ optical flow จับคู่เฟรมเพื่อกรอง probability และใช้ hysteresis (entry .62, release .54 โดย current probability ไม่ต่ำกว่า .50) ช่วยลดการกระพริบ ผลลัพธ์ถูกกรองด้วยสีพืชและ veto ที่กำหนด ไม่ใช่การใช้สีเขียวของภาพจริงตัดสินทางทั้งหมด

ช่อง threshold ขนาดไม่เกิน 128 พิกเซลและความหนารัศมีไม่เกิน 2 พิกเซลสามารถเชื่อมได้เฉพาะเมื่อถูกล้อมด้วย drivable ทุกจุด และ probability ปัจจุบัน/ที่กรองยังไม่ต่ำกว่า .50 ไม่เติมหลุมใหญ่หรือบริเวณที่โมเดลปฏิเสธชัดเจน แสดงจำนวนผ่าน `enclosed_uncertain_pixels`

Segmentation packet ใช้ label 1=drivable, 0=blocked และ 255=unknown/ไม่ได้วิเคราะห์ สีเขียวใน overlay เป็นภาพแสดง mask ไม่ใช่สีพื้นผิวจริง

## 2. การสร้างเส้นเหลือง

ใช้ calibration, distortion และ extrinsic ของกล้องฉาย label ไปยังระนาบพื้น (สมมติพื้นราบ) สร้าง grid .05 m ตรวจแถบกว้างตามขนาดหุ่นและ side margin แล้วหากลางช่วงเขียวที่ต่อเนื่องกันตามระยะด้านหน้า

Dijkstra ค้นเส้นทางที่เชื่อมได้บน grid แบบ 8 ทิศทาง โดยไม่ตัดมุมข้ามช่องที่ไม่ว่าง ต้นทุนประกอบด้วยระยะทาง ความห่างจากกลางช่วงเขียว และ clearance ใช้แนวกลางร่วมกับเส้นจากกราฟเป็นผู้สมัคร เลือกพิจารณาทางที่ต่อด้านหน้าได้ไกลกว่าเป็นช่วง .20 m ก่อนความใกล้กลาง/clearance พร้อมสำรองปลายทางซ้าย กลาง ขวา

Resample .025 m และทำ Gaussian smoothing หลายระดับ ตรวจ label ตามแถบเต็มความกว้างที่ตั้งฉากกับเส้นทุกครั้ง ความโค้งสูงสุดของเส้นที่ยอมรับไม่เกิน 4 /m เส้นที่ไม่ผ่านการตรวจไม่ถูกส่งให้ controller ระบบไม่ใช้เส้นแดงหรือ goal เพื่อเลือกแนว

## 3. การควบคุม

reference เก็บในกรอบ odom จาก TF ณ เวลา capture ใช้ Pure Pursuit กับ lookahead .35 m:

`kappa = 2*y / (x*x + y*y)` และ `omega_pp = v*kappa`

สำหรับ reference สด เพิ่ม feedback ของมุมไปยัง target (gain .60) และทิศของแนวเส้นจาก chord ประมาณ .30 m (gain .35) ในพิกัดหุ่น ลดความเร็วเมื่อเยื้องแนวด้วยตัวหาร `1 + .75*abs(bearing) + .35*abs(heading)` และหาก angular command เกินเพดาน ลด v/omega ในสัดส่วนเดียวกันเพื่อรักษาความโค้ง ไม่หมุนอยู่กับที่หรือถอยในโหมดนี้

เส้นเหลืองคำนวณกลางพื้นที่ที่สังเกตได้ เส้นน้ำเงินเป็นแกนหุ่นตามกล้องที่เยื้องศูนย์ controller เป็นผู้เลี้ยวหุ่นเข้าหา reference ไม่ได้เลื่อนเส้นน้ำเงินในภาพให้ตรงกัน

## 4. ความต่อเนื่องและการอนุญาต

การวางเส้นใช้ worker เดียวกับคิว capture ล่าสุด แยกจาก callback รับปุ่ม/odom และรอบส่งคำสั่ง 20 Hz เส้นเดิมนำกลับใช้ได้เมื่อเฟรมใหม่ตรวจพื้นที่ผ่าน ส่วนการ hold ขณะรอข้อมูลใหม่ยังยึด timestamp เดิม: เกิน .5 s จำกัด .08 m/s และหมดอายุไม่เกิน 2 s

Reference gap ที่ฟื้นตัวได้เป็นการพักศูนย์โดยคง session จากนั้นกลับมาได้เมื่อเส้นใช้ได้และยังกดเดินหน้า ไม่ reset เวลา/ระยะ/มุมสะสม Bridge ส่งคำสั่งศูนย์ที่สร้างใหม่เมื่อคำสั่งจาก safety ยังไม่มา/เก่า เพื่อหลีกเลี่ยงการขาด heartbeat โดยไม่ replay ความเร็วเก่า

ต้องมี enable, operator permission, teleop สด, odometry สดและ reference ใช้ได้ การปล่อยปุ่มบน terminal ตรวจด้วย key-repeat timeout ประมาณ .6 s; Space/k ส่งศูนย์ทันที Gateway บน ROS1 มี watchdog .25 s, lease และ budget ของตัวเอง Network/permission หายหรือถึงขีดจำกัดยังหยุดได้ ไม่มี auto re-arm ข้าม fault

## ขอบเขตและข้อจำกัด

ระบบนี้เป็น steering assistance ที่มีคนกำกับ ไม่มี autonomous destination navigation ไม่มี Nav2/SLAM/RViz ใน launch ชุดนี้ และ `subscribe_scan=false` จึงไม่ใช้ LiDAR เป็นเงื่อนไขหยุดสิ่งกีดขวาง ชื่อ executable `laser_safety` คงไว้เพื่อ compatibility; ในโหมดนี้ทำหน้าที่กรองคำสั่ง/permission/watchdog/budget

การตรวจ strip ใน mask ไม่ใช่การรับรองพื้นจริงหรือการตรวจ footprint/swept volume ทางกายภาพครบทุกช่วง โดยเฉพาะพื้นที่บอดใกล้หุ่นและเมื่อกล้องเห็นขอบทางไม่ครบ การเปลี่ยนกล้องต้องวัด calibration/mount ใหม่ ไม่มีค่า IoU, tracking error หรือ latency หลังปรับ middleware ที่ยืนยันเชิงปริมาณรวมอยู่ใน branch นี้
